# Capability Spec: Discovery

**Module:** `backend/app/modules/discovery/`
**Tier:** 3 — Controlled Expansion
**Owner:** Platform team
**Status:** API, Persisted, Tested (contract), Events Implemented

---

## Purpose

The Discovery module guides prospective customers through an AI-assisted conversation to identify their business pain points, match them to CBOS capabilities, and generate an implementation blueprint. It is the entry point that converts an unknown prospect into a provisioned workspace.

---

## Wedge Role

- Discovery is the top of the wedge — it fires before any other module is active
- A new contact starts a session (authenticated or optionally public) and chats with the AI assistant
- The assistant accumulates business context (industry, company size, pain points) across the conversation
- On completion the session produces a blueprint: a recommended solution package and the list of modules to activate
- `apply_blueprint` emits `workspace.activated` which triggers downstream provisioning of CRM, Sales, Inventory, etc.
- No other module depends on Discovery; Discovery depends on all modules indirectly through the capability registry

---

## Core Capabilities

| Capability | Route | Notes |
|---|---|---|
| List capability catalog | `GET /api/v1/discovery/capabilities` | Public — no auth required |
| List solution packages | `GET /api/v1/discovery/packages` | Public — no auth required |
| Create session | `POST /api/v1/discovery/sessions` | Authenticated; workspace-scoped |
| List sessions | `GET /api/v1/discovery/sessions` | Authenticated; returns workspace sessions only |
| Get session by ID | `GET /api/v1/discovery/sessions/{session_id}` | Authenticated; 404 if not in workspace |
| Send message | `POST /api/v1/discovery/sessions/{session_id}/messages` | Authenticated; calls AI assistant, persists exchange |
| Generate blueprint | `POST /api/v1/discovery/sessions/{session_id}/generate-blueprint` | Authenticated; sets session to `completed` |
| Apply blueprint | `POST /api/v1/discovery/sessions/{session_id}/apply` | Authenticated; requires blueprint to exist first (409 otherwise) |

---

## Access Model

- `GET /capabilities` and `GET /packages` are **public** — no `Authorization` header required
- All session and chat endpoints require a valid JWT (`get_current_user`) and workspace context (`get_current_workspace_id`)
- Sessions are strictly workspace-scoped: `workspace_id` is injected from the token, not from the request body
- Cross-workspace access returns 404 (not 403) to avoid enumeration

## Data Model

### DiscoverySession

| Field | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key |
| `workspace_id` | String(36) | Workspace scope; indexed |
| `actor_id` | String(36) \| None | User who started the session; nullable (reserved for public sessions) |
| `status` | String(30) | `active` \| `completed` \| `abandoned`; default `active` |
| `business_description` | Text \| None | Free-text business description |
| `industry` | String(100) \| None | Detected or provided industry (e.g. `retail`, `healthcare`) |
| `company_size` | String(50) \| None | `nano` (<5) \| `small` (5–20) \| `medium` (20–100) \| `large` (100+) |
| `detected_pain_points` | JSON \| None | List of pain point strings populated on blueprint generation |
| `matched_capabilities` | JSON \| None | List of capability IDs matched to the session |
| `recommended_package` | String(50) \| None | Package slug (e.g. `starter`) |
| `blueprint` | JSON \| None | Full blueprint dict generated by AI |

| Field | Type | Notes |

| `role` | String(20) | `user` \| `assistant` \| `system` |
| `content` | Text | Message body |
| `token_count` | Integer \| None | Reserved for cost tracking; not yet populated |
